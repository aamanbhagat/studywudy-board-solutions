# Phase 3 — Technical SEO infrastructure and structured data

Baseline: `6ceb77530`

## Result

The local production wrapper passes the Phase 3 runtime audit and the complete
312,176-URL corpus passes the metadata/click-depth audit.

- Sitemap index: 13 children, comprising one hierarchy sitemap and 12 question
  shards. All children are gzip-compressed, remain below 25,000 URLs (except
  the final 24,449-URL shard), contain one `lastmod` per URL, and total 312,176
  indexable URLs.
- Last modification: catalog row `updated_at` values are preferred when
  populated. The recovered catalog currently has no row timestamps, so the
  stable active-publication timestamp `2026-08-15T03:30:10Z` is used. Builds do
  not substitute the current date.
- Metadata: zero exact title/description collisions and zero collisions after
  Unicode NFKC, case, punctuation, and whitespace normalization across all
  312,176 indexable URLs.
- Canonicals: marketing, filter, preview, sort, stream, and search parameters
  resolve to clean canonicals. Valid chapter pagination preserves only `page`;
  `page=1` permanently redirects to the clean chapter URL.
- Structured data: all 13 route templates parse with zero local schema errors
  or warnings. The homepage has Organization, WebSite/SearchAction, and
  BreadcrumbList. Every template has one BreadcrumbList. Indexable question
  leaves have WebPage → Question → accepted Answer. Chapter pages retain
  LearningResource as a lower-priority educational signal.
- Internal linking: homepage → class → subject → chapter/pagination → question
  produces a calculated maximum question-leaf depth of 4. Subject directories
  link every chapter and all chapter pagination URLs; chapter pages retain
  textbook sibling navigation.

## robots.txt audit

Recovered production content before Phase 3:

```text
User-Agent: *
Allow: /
Disallow: /api/
Sitemap: https://studywudy-board-solutions.amanbhagat17089.workers.dev/sitemap.xml
Host: https://studywudy-board-solutions.amanbhagat17089.workers.dev
```

Issues found: internal admin/preview routes and search-result query URLs were
not disallowed. Static asset routing also answered `robots.txt` before the
Worker, preventing a runtime fix from taking effect.

Current policy:

```text
User-agent: *
Allow: /
Disallow: /api/
Disallow: /admin/
Disallow: /preview/
Disallow: /*?*preview=
Disallow: /*?*draft=
Sitemap: https://studywudy-board-solutions.amanbhagat17089.workers.dev/sitemap.xml
Host: https://studywudy-board-solutions.amanbhagat17089.workers.dev
```

The Wrangler asset rules now route SEO and indexable application paths through
the Worker, while JS, CSS, fonts, images, and other static assets remain on the
asset layer.

## Production-only acceptance steps

This recovery workspace was not deployed during Phase 3. Consequently, the
following external checks must be completed after deployment and cannot be
claimed from local validation alone:

1. Submit only `/sitemap.xml` in Google Search Console and confirm the index
   plus all 13 children are fetched with zero errors.
2. Run Google's Rich Results Test against one deployed URL from each template.
   Breadcrumb eligibility is the visible-result priority. Question/Answer
   markup is content-understanding hygiene, not an FAQ rich-result strategy.
3. Confirm the production robots response and invalidate any prior sitemap or
   HTML cache. The `incremental-cache-v16` namespace forces Phase 3 pages to
   regenerate after deployment.
